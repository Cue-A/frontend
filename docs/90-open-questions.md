아직 정해지지 않은 것들입니다. **여기 걸리는 내용을 혼자 결정하고 구현하지 마세요.**
이슈 단계에서 이 문서를 먼저 확인하고, 걸리는 항목이 있으면 이슈에 번호를 적어주세요.

정해지면 해당 항목을 지우고, 결정 내용을 관련 문서(`docs/01-conventions.md`,
`docs/design-system.md` 등)에 옮겨 적습니다. 이 문서에 결론을 쌓아두지 않습니다.

| 상태 | 뜻 |
|---|---|
| 🔴 | 막힘. 이게 정해져야 작업을 시작할 수 있음 |

## 디자인 시스템

### Q1. 🟡 다크모드 팔레트가 없습니다

Figma 파일에 다크 변형이 없어 라이트 팔레트만 토큰화돼 있습니다.
지금 구조는 Primitive 단일 계층이라, 다크모드를 넣으려면 `bg-neutral-0` 같은 클래스를
쓴 지점을 전부 찾아 고쳐야 합니다.

- 임시 결정: **라이트만 지원**하고 진행합니다.
- 필요한 결정: 다크모드를 할지, 한다면 Semantic 별칭 레이어를 먼저 넣을지.
- 걸리는 작업: 전역 색을 새로 쓰는 화면 전부.

### Q2. 🟡 `neutral-900` 과 `neutral-1000` 의 용도가 겹칩니다

Figma 카드에 둘 다 "제목 · 본문 기본색" 으로 적혀 있습니다.

- 임시 결정: **본문·제목은 `neutral-900` 만 씁니다.** `neutral-1000`(순검정)은 쓰지 않습니다.
- 필요한 결정: `neutral-1000` 이 실수인지, 별도 용도가 있는지 디자이너 확인.

### Q3. 🔴 `text-body-md`(14px) 와 `text-body`(13px) 이름이 너무 비슷합니다

잘못 골라도 에러가 나지 않고 화면에서만 1px 차이로 티가 납니다.

- 필요한 결정: 랜딩 전용 세트에 접두어를 붙일지(`text-landing-body`), 아니면 Figma 이름을
  그대로 둘지.
- 걸리는 작업: 랜딩 페이지 퍼블리싱.

### Q4. 🟡 배지 토큰 이름이 배지 내용에 묶여 있습니다

`badge-first-practice`, `badge-streak-3` 처럼 배지가 하나 늘 때마다 토큰이 3개씩 늘어납니다.
값은 이미 `primary` / `semantic` 과 동일합니다.

- 필요한 결정: 역할 기반(`badge-brand` / `warning` / `danger` / `info` / `success`)으로 바꿀지.
- 참고: 문서에 적힌 "동일 색상의 20% 배경" 규칙은 실제 Figma 값 5개 모두와 맞지 않습니다.
  `color-mix()` 로 계산하도록 바꾸면 **5색이 전부 바뀝니다.**

## API 연동

### Q5. 🔴 백엔드 base URL 과 인증 방식이 정해지지 않았습니다

- 필요한 결정: 개발 중 Vite proxy 를 쓸지 `VITE_API_BASE_URL` 을 쓸지,
  토큰을 쿠키에 둘지 헤더로 보낼지.
- 걸리는 작업: `shared/api/` 구현, 로그인 화면.

### Q6. 🔴 AI 응답 대기(최대 90초) 중 화면을 어떻게 보여줄지 정해지지 않았습니다

- 필요한 결정: 폴링인지 WebSocket 인지, 진행 단계를 몇 개로 나눠 보여줄지,
  타임아웃 시 사용자에게 무엇을 제안할지.
- 걸리는 작업: 면접 진행 화면.

### Q7. 🟡 `errorCode` → 사용자 문구 매핑표가 없습니다

백엔드의 `ErrorCode` enum 목록을 받아야 채울 수 있습니다.

- 임시 결정: 매핑에 없는 코드는 공통 문구로 떨어뜨립니다.
- 필요한 결정: 전체 코드 목록 공유.
